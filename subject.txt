# RAG Against the Machine - Project Summary & Quickstart Guide

This document summarizes the key requirements, rules, and technical details you need to know to start building your Retrieval-Augmented Generation (RAG) project.

## 1. Project Goal
Build a RAG system that answers questions about a specific codebase (the vLLM repository). The system must:
1. **Index**: Read the codebase, chunk the files, and store them in a searchable index.
2. **Retrieve**: Match user questions to the index and pull the most relevant snippets.
3. **Generate**: Use the `Qwen/Qwen3-0.6B` local model to generate a natural language answer based *only* on the retrieved snippets.

## 2. Technical Stack & General Rules
*   **Language**: Python 3.10 or later.
*   **Package Manager**: `uv` (The evaluator will use `uv sync`).
*   **Coding Standards**: `flake8` for linting.
*   **Type Checking**: `mypy` for static type checking. All functions must pass `mypy` without errors.
*   **Documentation**: Include docstrings for functions and classes (PEP 257 - Google or NumPy style).
*   **Error Handling**: Use `try-except` blocks to prevent crashes. Use context managers (`with` statements) for files/network connections to prevent memory leaks.
*   **CLI Library**: Python `Fire` to expose your pipeline commands.
*   **Progress Bars**: `tqdm` for long-running operations.
*   **Data Validation**: `pydantic` must be used for data models exchanged between stages (see section 4).

## 3. Project Structure

## 4. Mandatory Part Details
This section breaks down the core pipeline components required to pass the project.

### 4.1 Indexing the Codebase
*   **Goal**: Ingest the provided vLLM repository, split files into chunks, and persist an index.
*   **Time Limit**: Indexing the entire corpus must take **at most 5 minutes**.
*   **Chunking Strategies**: You must implement **two distinct chunking strategies**:
    1.  Python code chunking
    2.  Markdown / text chunking
*   **Retrieval Algorithm**: You must implement at least one of these two classic lexical methods:
    *   **TF-IDF**
    *   **BM25**
*   **Chunk Size**: Configurable via `--max_chunk_size` with a **default of 2000 characters**. Do not exceed this size. The grading tool (moulinette) rejects any source longer than 2000 chars, invalidating your output. Smaller chunks are fine, report the effect on your recall@k.

### 4.2 Retrieval
*   **Goal**: Match a question against the index and return the top-k most relevant snippets.
*   **Location Format**: Each result must return a `file_path`, a `first_character_index`, and a `last_character_index` (max 2000 chars wide).
*   **File Path Strictness**: The `file_path` must **exactly match** the corpus path (e.g., `data/raw/vllm-0.10.1/docs/features/lora.md`). The grader does a verbatim string comparison.
*   **Performance Goals**: On reference datasets, your system must reach at least **80% recall@5 on docs** questions, and **50% on code** questions.
*   **Retrieval throughput**: At most 90 seconds for 200 questions.

### 4.3 Answer Generation
*   **Goal**: Generate a natural-language answer using **Qwen/Qwen3-0.6B**.
*   **Execution**: Pass the retrieved context to the model and output structured JSON.
*   **Answer Quality Requirements**:
    *   **Coherent** and understandable.
    *   **Grounded** in the retrieved sources (no major hallucinations).
    *   **On point**: answers the specific question asked.

### 4.4 Mandatory Pydantic Data Models
You must implement the following Pydantic models to validate the data exchanged between stages. You can add extra fields if needed, but these bases are required:
*   `MinimalSource`: `file_path` (str), `first_character_index` (int), `last_character_index` (int)
*   `UnansweredQuestion`: `question_id` (str, defaults to uuid4 lambda), `question` (str)
*   `AnsweredQuestion`: inherits from `UnansweredQuestion`, adds `sources` (List[MinimalSource]), `answer` (str)
*   `RagDataset`: `rag_questions` (List[AnsweredQuestion | UnansweredQuestion])
*   `MinimalSearchResults`: `question_id` (str), `question` (str), `retrieved_sources` (List[MinimalSource])
*   `MinimalAnswer`: inherits from `MinimalSearchResults`, adds `answer` (str)
*   `StudentSearchResults`: `search_results` (List[MinimalSearchResults]), `k` (int)
*   `StudentSearchResultsAndAnswer`: `search_results` (List[MinimalAnswer]), `k` (int)

### 4.5 Output JSON Files
Each CLI command writes a JSON file conforming to the models above:
*   **Search Operations**: Writes a `StudentSearchResults` model (containing a list of `MinimalSearchResults` and `k`).
*   **Answer Generation**: Writes a `StudentSearchResultsAndAnswer` model (containing a list of `MinimalAnswer` and `k`).

### 4.6 Required CLI Commands
Your CLI must be built with Python Fire and run as: `uv run python -m src <command> [options]`. All input and output paths must be configurable CLI arguments and never hard-coded.
1.  **`index`**: `--max_chunk_size <int>`. Ingests `data/raw/` and builds the index under `data/processed/`.
2.  **`search`**: `<query> -k <int>`. Returns top-k sources for a single query.
3.  **`search_dataset`**: `--dataset_path <path> -k <int> --save_directory <dir>`. Runs search over a dataset JSON.
4.  **`answer`**: `<query> -k <int>`. Answers a single query using retrieved context.
5.  **`answer_dataset`**: `--student_search_results_path <path> --save_directory <dir>`. Generates answers for a dataset JSON.
6.  **`evaluate`**: `--student_search_results_path <path> --dataset_path <path>`. (For your own testing) Reports your recall@k against ground-truth.

## 5. End-to-End Walkthrough
During defense, your pipeline runs automated via these steps:
1. `uv run python -m src index --max_chunk_size 2000`
2. `uv run python -m src search_dataset --dataset_path data/datasets/UnansweredQuestions/dataset_docs_public.json --k 10 --save_directory data/output/search_results/UnansweredQuestions`
3. `./moulinette evaluate_student_search_results ...` (Evaluator grades your recall)
4. `uv run python -m src answer_dataset --student_search_results_path data/output/search_results/UnansweredQuestions/dataset_docs_public.json --save_directory data/output/search_results_and_answer/UnansweredQuestions`

## 6. Makefile Rules
Your `Makefile` must include:
*   `install`: Install project dependencies using `uv`.
*   `run`: Execute the main script.
*   `debug`: Run the main script in debug mode (e.g., using `pdb`).
*   `clean`: Remove temporary files/caches (e.g., `__pycache__`, `.mypy_cache`).
*   `lint`: Execute `flake8 .` and `mypy . --warn-return-any --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs`.

## 8. Bonus Features (Optional)
*Note: Bonuses are evaluated ONLY if the mandatory part is 100% complete.*
1.  **Semantic embeddings**: Add a vector index using a lightweight CPU model (e.g., `all-MiniLM-L6-v2`).
2.  **Hybrid retrieval**: Combine lexical (TF-IDF/BM25) and semantic rankings.
3.  **Incremental indexing**: Re-index only changed files instead of the whole corpus.
4.  **Caching**: Cache index and query results to speed up repeated queries.
5.  **Local HTTP API**: Expose querying and answering over a local API.
